# Opening scheduler validation and backup admission

The scheduler may reuse a fully validated, waiting ordinary Alpaca cycle until its execution wake. The bounded PostgreSQL witness selects the current generation's deterministic original or replacement identity. It covers the complete lower-generation predecessor set for the same deployment, account, takeover and decision, every materialized row version and every event version. Privileged rewrites, missing or extra predecessors, changes to events, control or lease changes, database restart, schema changes or an expired wake invalidate reuse. Debug, authorized recovery and owner-continuation histories have additional dependencies and always use full validation. A witness is for idle display and scheduling only. Every execution wake follows the normal checks.

One full lineage reconstruction reads each materialized predecessor and its history once within that call. Transport classification examines those same events. The next independent reconstruction reads evidence afresh.

The same scoped witness covers a completed ordinary obligation until its effective session closes. The scheduler recomputes its current obligation on every poll. A newly eligible obligation, actionable cycle, kill, takeover or changed history returns it to full discovery. The idle lease check returns the validated control row used to prove that live fence, avoiding another replay immediately after the check.

The production PAPER callback checks backup admission before consulting the external clock or entering the execution gateway. An exact, typed backup-proof contention at that admission point has the same pre-transport provenance as contention at the gateway entry lock. It may use the existing fenced entry retry only after the scheduler proves the command journal contains no possible transport for this attempt. Unclassified failures, LIVE, and contention after entering the gateway retain their existing recovery semantics. Failed or missing backup evidence still prevents submission.
