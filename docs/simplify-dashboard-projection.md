# One dashboard projection for each evidence boundary

The dashboard collector retains original recorded rows. Its fast publisher
combines them with fresh, scope-specific evidence in the existing owned
transaction. The signed dashboard receipt retains those original rows and the
review of their derived display. An HTTP read revalidates the receipt and
applies the same pure projection after its scoped overlays. Review and
acknowledgement use that projection and the existing strict subject and head
checks. They preserve all signed field shapes, native and receipt dependencies,
and original time limits. A display projection never restores authority by
undoing an earlier label or expired deadline.

Production uses the existing full composition worker and fast publisher.
Tests use the same signed composition boundary. Verification uses the existing
separate SHADOW and PAPER observations and their canonical scope identities.
The old one-pass publisher and combined observer have no runtime callers and
are retired. Full and fast workers retain their distinct deadlines, and
both active negative results and failed-attempt history remain authoritative.

Each owned read transaction computes native verification identities once and
passes those same identities to its scope receipt reads. Producer and consumer
transactions still compute identities independently. Holders, review heads,
receipt clocks, and publication and installation identities are rechecked at
their existing boundaries.

Automation owns the common native facts for a live cycle callback. Dashboard
broker display and optional scan deferral continue to select their own phases,
sessions, and original deadlines. They each retain their existing scope checks.
Share the close publication job binding and checkpoint identity checks with
preparation. Their callers still own the checks for actual candidate authority,
the verifier attempt, live worker, and effective deadline. These observations
grant no trading authority and use the caller's coherent transaction.

Qualification covers original evidence through publication, late scope changes,
expired display, a current failure, review and acknowledgement, superseded
observations, and close readiness handoff. Use private PostgreSQL and execute
guard-removal falsifiers for same-fence callback and matching publication.
