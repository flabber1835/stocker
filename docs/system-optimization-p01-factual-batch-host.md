# P01 grouped factual host orchestration

The host job resumes only root-admitted OWN526 through February 4, 2020.
The source epoch remains the existing 516 physical / 224 canonical files.
The source map and archived receipt are reused exactly, while the historical
515-file binding remains explicitly historical. All 439 prior driver files and
the prior request remain immutable. New factual registry, codecs, runtime and
proof contracts are described in `system-optimization-p01-factual-batch.md`;
epoch hydration/admission is described in `system-optimization-p01-epoch-resume.md`.

The dedicated workflow triggers only the new request on the existing research
branch. It prepares capacity with the frozen helper before staging, checks the
new source closure, and authenticates the frozen inputs/runtime. The host job
checks the actual capacity receipt and staging proof, then performs the real
encrypted marker roundtrip before fetching any parent or launching a worker.
The separate existing key is removed from worker environments. The approved
historical quote capsule is reused unchanged; no provider query or new upload
route is introduced.

The host reconstructs the original 515-file tree from its binding, then applies
the frozen CELG source renderer with the map's **223-file predecessor** financial
map. The result must equal the already admitted 516-file map and its 224-file
successor financial map. Passing the current 224-file map as the renderer's old
map would be a source-epoch error. Original source, successor source, admitted
parent and authenticated capsule are made read-only before workers start.

Every worker uses the existing offline, nonroot, read-only-root container fences:
two CPU, eight GiB, no swap, PID bound, capabilities dropped and no new privileges.
The new exact command is `/driver/p01_factual_batch_run.py --mode
qualify|economic|review --spec /out/spec.json`. Quote root and descriptor are
read-only mounts. Economic mode mounts the qualifier evidence read-only; review
mode mounts stopped financial evidence read-only.

The qualifier starts from original OWN526, proves a zero-session epoch resume,
then an eleventh-input zero startup, codec/action/component gates and two actual
canonical sessions. Its successful stopped proof is exported to a separate
qualification cipher **before** finance starts. Four root metadata files and
eight named qualifier proof files, plus actual inspection and logs, form the
normal fourteen-member export. A `log-copy-failure.json` is retained explicitly
when the existing stop helper cannot copy logs; missing logs are never described
as complete. No disposable qualifier book is exported as financial authority.

Finance starts freshly from original OWN526 in a separate worker and reproduces
the qualifier's epoch/input boundary and first two states. The bound ends June
29, 2020, before the unresolved MTCH2 event: 101 new sessions, target 627 closes.
The outside stopped reviewer uses the same source, input and quote context.
All private request files are whole copies of the exact public request bytes;
there is no line-ending or ignored-field serialization exception.

The proven `stopped_run` is reused without modification. It records and fsyncs
actual inspection in `finally`, stops a running writer, returns `wait_error`
alongside known actual stop metadata, and records log-copy failure separately.
The host copies private evidence only after this known stop. A qualifier or
financial writer with UNKNOWN stop has no mutable output snapshot. If only the
reviewer is UNKNOWN, the already stopped financial evidence remains exportable
without the active review directory. The successful qualifier cipher remains
available independently of later finance/review failures.

Public receipts and phase notes are atomic and allowlisted, containing only
scope, resource, stop, cipher commitment and static error metadata. Financial,
market and exception payloads stay private inside authenticated ciphers. The
normal public artifact contains capacity, staging, phase, marker, receipt and
two ciphers with seven-day retention. Early failures may contain only the public
receipts actually written; they do not imply a parent, worker or financial result.

Wait budgets are qualifier 2,400 seconds, finance 5,400, review 1,800. The proposed
financial step is 210 minutes and job 240 minutes, leaving 2,730 seconds within
the financial step after those waits plus 270 seconds of shutdown reserve.
Download, reconstruction, logs and both exports must fit this remaining bound;
root reviews the complete headroom before publication. The host remains closed
on resource-gate failure; it does not weaken the 12/10 GiB disk or memory fences.
Every surrounding workflow step is bounded explicitly: checkout three minutes,
capacity three, locked dependencies four, metadata probe two, staging eight and
upload five. Those twenty-five minutes plus the 210-minute orchestration step
total 235 minutes, leaving five minutes within the 240-minute job. An unbounded
upload or preparation step is refused by the workflow budget test.
Tests use metadata, real synthetic crypto and orchestration/stop stubs only.
Root alone publishes/selects a hosted run and admits any financial predecessor.
