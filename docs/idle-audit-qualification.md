# Idle operation and release handoff

The browser owns an acknowledgement attempt until the request finishes. A token
that has already been submitted cannot authorize a second attempt. A newly
observed eligible token can be used on a new operator click, including when it
arrives during an earlier request. Across software releases a fresh same-origin
document with a different controller fingerprint starts the new controller.
Within a release reconciliation preserves open inspections and the proof clocks.
The server retains one bounded, detached presentation input for fallback.
It renders the explicitly non-current view only when a navigation needs it.

The source catalog interns repeated historical file revisions. Every release
continues to reconstruct directly from the independently pinned anchor and must
match its original complete inventory and digest. No earlier release is needed
to decode a later one. The external size limit and candidate identity checks apply.

Shadow ledger storage preserves its existing logical JSON and sequence checksum.
An append may reuse immutable, content-addressed complete groups already stored
with the same canonical bytes. A changed group, partial tail or legacy input
goes through normal encoding. Private restore and replay continue to authenticate
every referenced group and the entire ordered sequence.

Idle qualification observes the interval from contention through recovery and the
next session boundary. It records individual transitions, work admissions and
maximum proof age. A later successful poll cannot erase an earlier expiry.
Qualification runs in an isolated environment with no broker credentials.

## Historical source compatibility

The operational reader and the historical price-domain conversions have
different lifetimes. Remove the network adapters and keep the offline
arithmetic for certified tapes. For a module rename or comment-only edit, an
exact old-to-new source witness must bind the released bytes, the new dependency
graph and the previously qualified economic contribution. Unknown source bytes
retain their actual identity. Restored records keep the original provider,
universe, book and action identifiers. The release inventory records retired
paths explicitly. A missing current file outside that list refuses admission.

Run the persistent automation loop against a disposable private PostgreSQL
cluster with matching XNYS decision and execution sessions. Drive its market
clock from the preceding close to the next opening callback. Database leases,
observer deadlines and the panel's five-minute proof clock use real time.
The nightly campaign compresses market time into four hours of uninterrupted
wall time. The local runner can use the actual interval as its duration.

Inject short exclusive corpus-writer holds from another database session at
different phases of the control polls. Journal the durable cycle transitions,
the root panel row before and after every control wake, original proof times,
fence, observer starts, writer holds and simulated opening callbacks. A gap
that crosses the original proof expiry fails the run even when the next read
already shows a renewed root. The private campaign supplies fixture inputs,
authority and broker observation. Evaluation of freshness, retry admission,
lease ownership, process supervision and cycle scheduling use production code.
