# Worker dependency notifications and confirmed recovery

Decision: 2026-10-23, before implementation. The owner authorized cause/time
diagnostics and a coalesced recovery notice, qualified locally while the source
job continues and installed only after publication and Monday's saved plan.
The owner-authorized local PAPER delivery and suspension of backup/restore work
remain in force. Trading, source acquisition, locks and deadlines do not change.

## Original failure evidence

Capture only reviewed typed causes on the existing dependency-availability
path. Preserve its actual UTC event time, allowlisted operation stage, original
qualified exception type, target session, observation identity and current
runtime identity. Walk only the already reviewed explicit exception causes;
integrity failures and unrelated exception contexts remain terminal. Never
publish raw exception text, URLs, credentials or provider response content.
Use explicit stages at the existing publisher boundaries, including the initial
acquisition lock, references, prices, validation and publication. Attach this
diagnostic before failure recording or cleanup; a cleanup lock refusal cannot
replace the original error. Missing evidence is explicitly unavailable.

The worker logs the bounded structured diagnostic and best-effort persists the
first immutable warning to the existing outbox before returning its unchanged
exit code. Diagnostic publication is finite and cannot change the worker's
economic outcome or extend its budget. The supervisor retains its fallback if
the worker could not report. Reuse an existing per-session warning unchanged;
retries and changing timestamps must not mutate its first payload. This uses
the existing outbox as notification history, without a second incident registry,
schema migration or financial cursor. A database outage may prevent outbox
persistence; the structured process log remains evidence of the actual cause.

## Exact publisher diagnostic source seam

The publisher contributes to the existing economic source identity. Adding
diagnostics therefore requires a narrow administrative seam before deployment;
it must not change the signed strategy, reconstruct the book, or loosen standing
paper authority. The independently verified installed publisher at commit
`596e8496bb0028498847f8e8a4afb26df3f786ba` supplies the unchanged economic source
contribution. Only the exact reviewed successor publisher bytes may inherit it.
The full executable identity still includes the actual successor and seam code.

Qualification strips only the exact added literal stage assignments and the
two diagnostic statements before failure recording, then compares the complete
remaining module AST with the installed baseline. It must reject neighboring
economic edits, changed hooks, unknown source bytes and missing diagnostics.
The runtime mapping is closed to this source pair; it never accepts an arbitrary
publisher or ignores an economic function. Existing source seams and baseline
fixtures remain unchanged. This follows the administrative-source principle in
`retained-state-activation.md`, and adds only the explicitly named publisher seam.

## Recovery evidence

Send one INFO `SHADOW_DEPENDENCY_RECOVERED` notice per original dependency
warning, keyed by that warning's immutable alert ID. Require a subsequent
canonical `SHADOW_GO` / `VERIFIED` result for the matching actual current closed
decision session, under the configured observation and actual admitted runtime,
after the warning time. Do not replay recovery pushes for older historical
sessions when this feature is first installed; retain their records as history.
Require a delivered per-device receipt for the original warning. A running
process, resumed download, successful HTTP request, waiting result, unrelated
session or expired proof is insufficient. Recovery concerns the verified
strategy update; it does not claim that the separate next-open plan or orders
are complete. Repeated successful workers and restarts cannot duplicate it.

Legacy generic dependency warnings remain immutable. They may earn a recovery
only when their established session key and canonical primary observation are
unambiguous; never invent the missing historical cause or attempt identity.
Reporting failure does not acknowledge, delete or soften a warning or critical
incident. A later ordinary verified invocation may retry recovery publication.
This narrowly supersedes the no-recovery-push rule for shadow dependency WARNs;
leadership, integrity, broker-UNKNOWN and critical-alert policy are unchanged.

## Phone copy and transport

Dependency warnings name the specific known condition and say the update will
retry, rather than implying the worker stopped. Show the original dated event
time with an explicit Pacific zone. The scheduler's typed `SourceDataPending`
REFRESH warning says closing data is not ready, separately from worker failure.
Recovery identifies the warned incident and its original time plus the later
verified recovery time. Permit only this new INFO event through the existing
push adapter. Fill, critical, enrollment and plan-ready behavior, subscriptions,
service worker and browser permissions remain unchanged. Recovery fanout is
restricted to the original warning's delivered device identities or their
authenticated explicit successors; unrelated newly enrolled devices receive no
recovery for a warning they never received. Enrollment/rotation must retain the
existing recipient-snapshot and expiry rules. Delivery acceptance
still does not prove when a physical phone displayed the notification.
