# Time-bounded joint system research

## Decision and scope

The owner approved proceeding after requesting full-system optimization and speed.
The initial wall-clock research budget is four hours, including implementation,
hosted input staging, measurement, search and review. This is a bounded search,
not a claim to solve every architecture or prove a global optimum. PAPER,
production source selection, broker APIs, databases and shared host workloads
remain outside the experiment. Only the existing research branch and PR 542 are
used. The research branch incorporates verified main
`98bf83bf7644fb278e811edf26272b4c204b1bbe`; the economic reference remains the
unchanged archived 514-file source and authenticated historical dataset.

The completed Owned55 search is retained. Its training improvements and absence
of later treatment do not establish that the production defaults are optimal.
This experiment must vary stock selection and parent risk control as well as
the final Owned55 overlay, or explicitly report which portions were not reached.

## Measure before choosing a candidate count

The first hosted stage measures the unchanged canonical replay, including input
preparation, Core transition, controller and serialization. It forms a distinct
measurement origin with the original 299 feature observations and at most six
formation transitions. It is a throughput experiment, with no performance score,
candidate selection or CAGR/drawdown claim. It is not continuation or recovery
of any failed earlier job. Its retained financial prefix is never relabelled as
a candidate book.

An ordinary unprofiled transition and a separately identified profiled transition
are measured separately; profiler overhead must not be used as ordinary replay
speed. The exact recorded formation rows must equal the original baseline bytes.
The checkpoint must restore canonically and every committed journal prefix/tail
must verify. An independent stopped reviewer makes these checks before timings
are admitted. No financial computation is executed locally.

The engineering limit is 60 minutes. If an exact reusable harness cannot fit the
remaining compute budget, publish measured coverage and the limiting cost. Do
not consume the entire budget on qualification without an explicit partial
outcome. Roughly half of the total budget is reserved for complete finalist
replay, independent accounting and a report. The count of candidates follows
measured throughput, never an invented estimate. A hard deadline produces a
preserved partial result rather than silent extension or an optimality claim.

## Search families and parameter ownership

The source inventory, baseline values, bounded alternatives and actual formula
sites are recorded before scoring. These components are economically distinct:

* Core selection: long momentum and skipped recent horizons, freshness threshold,
  leadership fraction/minimum population, durable-score volatility horizon and
  five-session median ordering. The actual Median5 mixed-precision formulas are
  the reference; the generic v1 signal function is not an interchangeable proxy.
* Core capital and exits: number of slots and consistent NAV/slot admission,
  admission cadence, close-based trailing retention, one-time review age and
  separate slot/security cooldowns. Persistent episodes, issuer restrictions,
  reservations and positive cash-clipped fills remain canonical.
* Parent Sentinel: ordinary drawdown/exposure, slow and fast entry thresholds and
  confirmation counts, healthy recovery thresholds/counts, champion recovery
  persistence and R40 floor. Recompute holding-dependent observations for each
  Core path.
* Correlation/breadth: current residual correlations, minimum sample count,
  neighbor cutoff/count and damaged/green classification. Retired sector labels
  must not replace the current correlation machinery.
* Owned55: the nine previously mapped latch/ceiling parameters, jointly with the
  parent rather than assuming a fixed parent is optimal.

Architecture alternatives (periodic rebalancing, volatility-based position risk,
per-holding protection) are separate named model families. They are not quietly
introduced as parameter changes, and are not claimed tested if the budget only
reaches the existing architecture. A per-holding rule changes Core or a new
account overlay, not the meaning of the existing scalar Sentinel membrane.

Costs, price domains, corporate-action facts and missing-data conventions are
fixed modelling assumptions, not favorable parameters to optimize. Exposure is
long-only and unlevered. Data remain the retained Sharadar archive; no new paid
provider, LLM forecast or production data acquisition is required.

## Exact reuse and search sequencing

Market observations, eligibility facts and holdings-independent feature arrays
may be cached with exact source/date/input bindings. Only equal inputs and
formulas may share results. Each changed Core setting owns fresh formation,
positions, cash, pending orders, actions, stop peaks and cooldown state. It must
produce its own holdings path and holding-dependent controller observations.
Each such Core path may then serve many independent Sentinel configurations.
Do not apply new selection settings to the old holdings trace.

Use deterministic space-filling coverage of bounded parameter blocks and their
interactions rather than a Cartesian explosion. Include the exact baseline and
multiple diverse finalists. Collapse configurations only on proven equal full
economic paths, retaining every identity. Never use later-period metrics to
retune thresholds or replenish the shortlist.

Before scoring, freeze chronological development windows and locked later
evaluation windows, including multiple market regimes. Rank growth under
several explicit drawdown budgets and report the Pareto frontier. Use training
only for search/selection; disclose all previous examination of historical data.
Known history is not unseen out-of-sample evidence. The final number of windows
and candidate count must be budgeted from the timing stage before performance
is inspected, with any reduced coverage stated explicitly.

Complete selected 2008-2026 replays require actual canonical Core holdings,
cash/receivables, actions, costs, overnight/intraday timing and serialized
continuation. Scalar-account screening remains labelled as such and cannot
stand in for persistent account-share or protected-limit PAPER execution.
Independent checks target the baseline equivalence and the economic changes,
not redundant ceremonial validation of already completed components.

## Isolation, evidence and delivery

The hosted worker uses the previously approved encrypted release and pinned
offline image, read-only source/input mounts, no credentials or network, a
private bounded output and proven stopped worker/reviewer identities. Actual
source, request, runtime and input hashes bind every output. Checkpoints,
journals, logs and timing evidence are AES-GCM encrypted in the same approved
public-repository Actions artifacts for seven days; the key stays separate.
No plaintext financial payload is logged publicly. Output size is bounded
before encryption; only completed authenticated files receive final receipts.
UNKNOWN stop outcomes never admit a financial snapshot.

Preserve failed/refused and negative outcomes. No automatic production promotion,
main merge, deployment, parameter tuning after evaluation or protected cleanup.
Report what was actually evaluated, what improved and what remains uncertain.
