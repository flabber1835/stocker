# Close dependency failure diagnostics

Decision recorded before implementation, 10 November 2026. The owner approved
a local PAPER patch from installed source `42d775b6952138191f89deb5054f97c079624bc2`.
The close capture shows three PREPARE refusals during an ordinary maintenance
proof. All three durable cycle events report the failed absent-media probe. The
original strict cause was lost from those events. The shared owner lock and
recorded hash interval point to contention. The retained evidence cannot
recover the initiating exception or establish the previous byte proof's age.

## Preserve both backup admission outcomes

The strict runtime backup authority owns the initiating failure. When selected
continuity also refuses, preserve the strict exception as the cause and retain
the fallback exception as context. Export two closed reason codes through the
existing callback failure detail. Identify common proof owner contention,
original proof expiry, selection movement and media read failure by their
existing typed conditions. Keep an explicit generic strict-unavailable code
for other temporary refusals. Identify the absent-media probe refusal at its
producer with a subtype of the existing temporary backup exception. Other
temporary continuity refusals retain their own generic outcome code. Arbitrary
exception text and connection values remain inside the process.

Preserve already typed strict backup failures before raw OS and SQL media
error conversion. The temporary backup hierarchy derives from ConnectionError
and therefore OSError. Treating that inheritance as evidence of media failure
would mislabel the common owner's refusal before the fallback even begins.

The same strict and continuity checks run in the same transaction boundaries.
Success, permanent refusal, retry classification and original proof clocks
retain their current meaning. The 600-second dashboard chain lifetime and the
300-second byte proof lifetime remain separate. An outstanding owner or expired
proof provides no new permission to admit a mutation. Qualification exercises
the real callback and durable PREPARE retry path with both reasons and checks
that removal of the reason preservation is detected.

## Attribute projection deadlines at the parent

The projection parent owns each finite initialization and collection deadline.
For its own timeout, retain the closed parent phase, the original monotonic
deadline and budget, elapsed time at timeout, and the outcome of the existing
bounded child reap. A collection timeout reports the parent's wait or result
boundary. The child's last internal operation is unknown without an observed
child record. If cleanup fails, retain the initiating timeout and keep track of
the process for the existing unreaped worker guard.

The fast and composition publishers emit one closed diagnostic through the
existing immediate nonblocking stderr path. Include the original last accepted
publication expiry for that publisher, or null when it has none. That clock is
diagnostic and supplies no new authority. The worker and publisher keep their
existing budgets, retry decisions, positive result protocol, conservative
failure handling and shutdown ownership. No private arguments, child output,
exception messages or additional checks enter this diagnostic.

If a fast result reaches its original publication expiry, retain that UTC
expiry and the UTC comparison clock. The monotonic worker deadline is absent
from that record because it was the publication clock that refused delivery.
An invalid elapsed clock has its own closed stage and the worker remains owned
as before. Diagnostic emission uses the existing atomic pipe writer directly.
An unavailable sink cannot add the ordinary reporting helper's fallback wait.

Exercise real spawned timeout and reap, the publisher's retained expiry, and
the actual nonblocking diagnostic record. A falsifier must detect loss of the
original expiry or deadline phase. Keep the timeout and success boundaries
unchanged when the diagnostic sink is unavailable.
