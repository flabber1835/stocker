# Observing a fenced software installation and PAPER activation

On November 18 the full installer completed once. During the two observer
handoffs, the mobile dashboard lost current financial evidence for roughly two
and eight minutes. The activation coordinator reported PREPARING throughout a
six-minute financial validation. Its own command journal continued to advance.

Expose the current host operation to the dashboard independently of PostgreSQL
and the signed financial collector. The canonical installer and activation
owner publish a short diagnostic phase in a dedicated directory under the
configured authority root. Mount only that directory read-only in the panel.
The record contains a fixed public phase code. Opening the record for a
bounded read and checking its exclusive kernel lock ties the message to a
live owner. A new owner creates a new inode. Exiting, crashing, or waiting
between activation attempts relinquishes the lock. Missing, unsupported or
unreadable observations leave the indicator unavailable. Display failure has
no effect on release decisions.

The coordinator identifies the supported financial GO explicitly and reports
its allowlisted backup, preparation, parity and database-health stages. The
panel can show progress during an observer handoff while independently
identifying retained data, unavailable current evidence and existing incidents.
Only a signed financial publication can restore its original readiness and
acknowledgement eligibility.

The signed image selection already authenticates the manifest reference, image
ID and source revision together. Use that exact inspected pair during the
same invocation when rechecking role images. Read each container incarnation,
configured reference, running state and health afresh. The quiescent review
schema installer already requires disabled control, the durable kill and the
invalidated lease within its database transaction. Use that guarded result at
selector publication, retaining the independent post-deactivation check. A
rejected transaction prevents selection.

The activation coordinator verifies the installed source before GO. After GO,
the reviewed software verifier checks the clean branch, HEAD and origin/main
again before the first financial mutation. A second adjacent Git preflight
would repeat those same observations.
