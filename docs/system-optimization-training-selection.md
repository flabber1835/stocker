# Hosted training-only aggregation

Use completed, independently reviewed numerical artifacts as the selection
inputs. Authenticate each exact GitHub artifact, receipt, AES-GCM ciphertext,
manifest and every inventory member before reading training records. Admit only
actual stopped-zero/noOOM/fenced numerical workers and reviewers with the exact
complete Core checkpoint binding. Retain the source artifact and admission
receipt; never infer success from a workflow conclusion.

The selector receives an envelope containing only declared Core parameters,
chronological availability, common factual-basis identity, review hash and one
training-period record set. It receives no later-period metrics. Verify the
profile hash against every training document, the complete4096 joint registry,
and the same factual basis across all admitted Core paths. Missing or refused
paths remain explicit unknown coverage. Require the official baseline and its
full-path equality receipt. Do not replace that risk benchmark with a weaker
individual candidate's benchmark.

On hosted compute, the existing exact constrained-growth selector produces the
2020 and2022 locks. The existing initial-observations-only acquisition function
allocates the predeclared four further Core calculations per cutoff. Preserve
every acquisition score/choice and the initial unknown set. These are compute
allocation predictions, not stock-return forecasts or evidence of an optimum.
No evaluation-period observations may be added to either training interface.

Only the training-selected finalists proceed to direct canonical classifier,
controller and funded-account confirmation. Later-period performance is read
after that lock. Existing failed paths, provider/action conventions and negative
results remain in the final coverage report. This step makes no production
change, new trial origin, parameter-space expansion or global-optimum claim.
