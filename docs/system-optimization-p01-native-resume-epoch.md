# P01 admitted OWN627 transport and epoch hydration

The native continuation starts from root-admitted OWN627, June 29, 2020, with
eleven archived inputs and the existing 516-file physical / 224-file canonical
source epoch. It introduces no new input or source boundary. The previous
456-file driver closure and all financial source bytes remain immutable.

`p01_native_resume_parent.admit(root, key, spec)` authenticates the exact retained
41403517644 artifact, both ciphertexts and complete inventories, actual capacity
receipt and export marker, published request bytes, and all three actual stopped
offline workers before parsing the private financial checkpoint. It uses the
unchanged source-bound generic AES-GCM/inventory extractor and stop-fence
function with explicit new transport scope; it does not reinterpret an old
financial authority. `validate_contents(root, spec)` performs raw hash/JSON
checks only: actual627 gzip/outer/inner/state/input, exact base, all eleven input
documents in original order, four committed prefixes with no current tails,
archived source receipt/map/binding, and every retained book/lineage checkpoint
gzip. The public predecessor metadata carries hashes and relative names only.

`p01_native_resume_epoch.historical_epoch(old, out, spec, ...,
checkpoint_path=None)` authenticates the approved historical quote first,
registers the unchanged old nine contexts and CELG tenth codec, then registers
the frozen grouped factual eleventh codec and loads every archived document in
order. The eleventh document retains its original OWN526 predecessor and raw
430c69 hash. Its parsed model hash is a different domain. It must never be
relabelled as an OWN627-created repair. Caller-owned book/journal/lineage copies
must already exist; the context does not write or advance a financial book.

Only after those checks may caller Ledger/SessionState restoration occur. The
context yields parent, source_map, quote, descriptor, eleven loaded objects,
source_gate, source_receipt_path and archived `source_args`. The new source gate
recognizes only the actual admitted627 checkpoint and exact archived150a2
receipt, reconstructs the identical current base and returns `(base, None)`.
The archived flag is necessary because canonical base construction omits the
source receipt field. `None` causes no repeated source event. The new gate has
no input-adoption operation and cannot authorize a twelfth document. Legacy
receipt schemas continue through the unchanged canonical loader.

Hosted qualification must prove normal zero-session627 startup preserves the
entire checkpoint, all four prefixes, and actual source AND input watch-event
counts. It must then run the actual June30/July1/July2 full-runtime qualification
before a separate fresh original627 financial continuation. Qualifier state
cannot become the financial predecessor. All new checkpoint restores, actions,
pending orders and partial/refused durable-prefix evidence remain subject to
the caller's canonical guards and independent review. No such financial
transition or canonical restoration runs locally during helper preparation.

Local tests use typed metadata, real synthetic AES-GCM, source AST and stubs.
They include wrong predecessor/request/source/receipt/doc-order/GCM/inventory,
missing actual codec registration, changed full checkpoint, a twelfth input,
