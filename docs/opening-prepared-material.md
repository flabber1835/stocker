# Reusing the work behind a saved opening plan

The closing scheduler owns plan preparation. Its independently supervised opening callback can reuse the same verified strategy, published market inputs and account sizing when their inputs are still identical. The handoff contains data produced by the canonical verifiers. The normal gateway continues to calculate the current readiness verdict and enforce the current account, order, certificate, lease, kill switch, budget, session and submission deadlines.

Use one bounded, atomically replaced JSON file per kind of verified material in the automation container's private scratch directory. One staging file per slot bounds disk use after an interrupted write. Bind authentication to the exact cycle, account, rollout, configuration, runtime revision, physical database and current input versions. Validate the database's physical identity, guarded DDL epoch and relevant row versions while the current publication is pinned. A changed input, another release, missing file, invalid signature or incompatible older plan runs the full verifier. A process restart on the same database and release can read the existing material. A replacement container warms its own scratch directory.

The checkpoint remains subject to current shadow transport approval, prospective attestation and a fresh source-final date check. The sizing handoff names the saved plan, current shadow record and predecessor share and action evidence. Caller-local memoization still fences repeated reads within the callback. The trader obtains fresh holdings, cash, outstanding orders and exact fill evidence before submitting under the existing grant.

After startup the current leader may encounter a waiting plan prepared by an older release. Its first eligible idle wake starts one broker-free reader to verify that exact plan while there is ample time before the open. The reader uses read-only transactions and an independent process deadline. Before any financial callback the scheduler terminates the reader, reaping it immediately when possible or on a later wake. A reader waiting on kernel I/O cannot delay the callback or start a replacement reader.

The database visibility identity includes the effective role, login role, row-security setting and search path. Each dependency must resolve to its actual public relation. A temporary or alternate schema masking one of those tables prevents reuse.
