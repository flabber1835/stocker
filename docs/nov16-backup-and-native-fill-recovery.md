The combined backed PAPER patch extends the staged opening repair. It retains
the installed book, durable account binding, command identities, exchange

## Backup retry decisions

Consecutive exact automated execution-entry backup refusals must increment the
same bounded busy counter used for other backup-contention retries. Record the
original execution deadline on the diagnostic that positively proves no
transport was attempted. The dashboard can project that durable fact without
granting trading authority.

On November 16 a PostgreSQL backend OOM dropped the maintenance client's
connection. Its proof failed while hashing, unlock acknowledgement was lost,
and the host removed the named worker. Ordinary database failure handling
then waited five minutes. Distinguish an operational or interface error on an
owned broken connection, with a compatible connection/shutdown SQLSTATE when
one exists, from database integrity failures, policy refusals, and unknown
cleanup. The worker reports this specific failure with the original failed
unlock state. The host may use its existing bounded early schedule only once
it confirms exact worker removal. The next attempt must open a fresh database
connection and obtain the same exclusive proof lock before any verification.
The existing receipt, content checks, original clocks, and restore limits
continue unchanged. Worker failure never creates a valid proof or implies
that an unlock succeeded. The source qualification must cover the installed
native host parser and worker together.

## Discover native fills independently

The existing bounded PAPER GET-only collector could not find the November 16
MTD fill until the journal recorded positive progress. Admit an owned active
command with an exact acknowledged native order identity to a fill probe even
if local fill quantity is zero. A native order with zero fills is ordinary
waiting. An order with greater native progress is still subject to exact
account, order, instrument, immutable quantity or notional, and native fill
activity checks. Select the same finite number of candidates per invocation
and rotate the starting slot across supervised passes. Prioritize neither a
permanently working order nor an already-covered fill over the entire cohort.
Both durable-ledger and GET-only collection retain the existing immutable
fill idempotency key. They do not confer any financial settlement authority on
notification evidence. Preserve the previously selected LIVE collector scope.

Apple's HTTP 201 evidence establishes sender acceptance. Device-side
presentation of the November 16 alert is unresolved. The backed local handoff
