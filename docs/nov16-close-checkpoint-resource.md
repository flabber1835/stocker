# November 16 close checkpoint storage

At 13:18 Pacific on November 16 the 1 GiB PostgreSQL cgroup killed the shadow worker's backend while it was converting the daily checkpoint to JSONB. The killed backend held roughly 810 MiB of anonymous memory. The adjacent immutable input insert and the signed checkpoint update each submitted the same large daily input as structural JSONB in one transaction. The previous row-version fix removed the old checkpoint from the compare-and-swap parameters. It left the new document and its duplicated input in the write path.

Continue using `sentinel_processed_sessions` with the existing cursor names, session keys, archive conflict semantics, and physical compare-and-swap witness. For new daily and reconstruction commits, store the immutable input once as a base64-encoded bzip2 level-1 stream of the exact ASCII canonical JSON. In the production-sized sample this encoding left the retained archive smaller than the legacy archive and added 0.84 seconds of decoder time over zlib level 6. Bound the canonical payload to 128 MiB and the compressed payload to 32 MiB. Reject oversized, malformed, truncated, trailing, or noncanonical input before admitting it to the checkpoint. These ceilings limit PostgreSQL to one opaque archive value and bound client decompression independently of the incoming bytes. Use the existing archive row so the cursor, shadow record, and input remain part of the same atomic commit and backup timeline.

Keep every checkpoint header field available at the existing JSON paths and replace its repeated `input_value` with an envelope-level SHA-256 reference to the archived canonical input. Hydrate the full logical checkpoint from the matching observation and session before validation. Verify the canonical archive digest and the original checkpoint HMAC over the hydrated payload using the existing purpose and key. A compact cursor with invalid archive evidence fails closed. The full logical payload, shadow record input digest, and runtime interfaces remain byte-for-byte equivalent under canonical encoding. The reader continues to validate legacy inline checkpoints with their existing uncompressed archive and can advance a legacy cursor directly. Cold-start checkpoint encoding remains its own format.

This change uses the existing schema and has no table migration or historical rewrite. Backups can contain legacy and compact records in the same closure. Read, restore, and forward-continuation qualification must include both forms. Once a compact checkpoint commits, restoring service over that state requires a binary with the compact-format reader. Release rollback to a pre-reader binary requires its qualified pre-cutover data or its original checkpoint format. During a pre-open code-only cutover before a successor commits, the previously committed state remains in its existing format.

Pin the exact checkpoint implementation transition and archive codec in the existing review witness so the change preserves the economic source identity only for the qualified storage implementation. The transition confers no trading or publication authority.

## Private PostgreSQL qualification

Matched the installed 16.14 image, 1 GiB hard memory ceiling, no additional swap, and 1.5 CPU limit using disposable loopback-only PostgreSQL. The synthetic canonical input contained 339,600 nested price bars and 69,307,071 ASCII bytes. Two legacy structural JSONB values consumed 10,243,615 and 10,244,178 bytes. The compact archive occupied 8,952,327 bytes and its cursor 992 bytes. Legacy write and commit took 14.419 seconds and reached the full 1 GiB cgroup ceiling. Compact write and commit took 10.973 seconds and the cgroup peaked at 126,627,840 bytes with zero memory-limit or OOM events. Timings include client serialization and compression, and host load differed between runs. The corresponding whole synthetic restart checks took 6.195 and 11.826 seconds, so this qualification establishes reduced database memory and writes, with no claim of a cold-read speedup.

The compact test advanced a legacy cursor by physical compare-and-swap and retained its legacy archive in the same lineage. A streamed `pg_basebackup` passed `pg_verifybackup`. A separate restored server authenticated the full compact reconstruction checkpoint in a read-only repeatable-read transaction and returned the same logical payload, while the prior legacy archive remained readable. Production archive rows were sampled for sizes through metadata-only queries. The large qualification payload was synthetic and used no production data.
