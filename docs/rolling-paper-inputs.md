# Rolling inputs at the paper execution membrane

The NAS has never passed GO. This is first-deployment integration, not adoption
or migration of an operational book. The existing signed paper authority,
account binding, writer lock, guarded broker transport, UNKNOWN handling and
long-only envelope remain required.

## One strategy book

Paper preparation from a rolling publication requires the reviewed dual-shadow
configuration and its current signed rolling runtime result. It sizes the
existing canonical shadow decision against independently observed account
capital using the existing immutable dual-plan authority. It never initializes,
warms or replays a second strategy book. Inspection, execution and recovery
revalidate that same authority; the publication's DATA_ONLY proof cannot stand
in for shadow or broker authority.

## Explicit execution readers

Add a version-dispatched execution input boundary. Legacy readers retain their
snapshot refusal. Execution pins the ordinary publication lock, authenticates
its receipt and exact operational snapshot/job/manifest binding, and obtains
the frontier from that publication. Rolling readiness uses the existing current
snapshot validator. Fresh broker guards independently verify the same versioned
publication contract before and after transport.

Close sizing marks come from the snapshot's unadjusted close domain, including
BIL, and remain Decimal at the execution boundary. Permanent identity and
metadata come from the bound immutable reference bundle. Next-open resolution
may extend an explicitly non-delisted listing ending at the immediately prior
published close by exactly one exchange session, only in the absence of a
competing successor. Historical lookup remains point-in-time and cannot reuse
that extension for another date. No current ticker is guessed for an unmapped
broker asset.

Corporate-action reconciliation consumes snapshot bars, benchmark domains,
bound ACTIONS and normalization split dispositions through the existing scalar
and material-event algorithm. It does not implement another split policy.
The publication-bound [action archive](rolling-history-retention.md) retains
the accepted action interval and BIL predecessor evidence after prices expire.
Command bases within that coverage remain usable without historical prices;
bases before its initial coverage still refuse explicitly. Older publications
without an archive retain the snapshot-window check. Data beyond the published close grants no
negative pre-open action authority: the existing affirmative pre-open contract
and unsupported-material-event fence remain unchanged.
The informational mirror's later unit check uses this same action reader.
Account-scoped paper dividend quarantine reads the same bound ACTIONS and raw
price domains through the existing entitlement calculator; an empty legacy
table cannot suppress a rolling snapshot's unsupported paper entitlement.

## Service integration and validation

For rolling publications automation refresh validates the already current
shadow decision and snapshot. The broker-free shadow service owns acquisition
and continuation. Paper automation cannot run legacy catch-up, replace the
shadow publication, or manufacture a new genesis when shadow progress is late.

Exercise real PostgreSQL snapshot publication and shadow approval through paper
preparation, immutable plan re-derivation and execution-reader recovery using
synthetic account/broker evidence. Check raw-price domains, ticker reuse,
next-session bounds, split/disposition agreement, BIL predecessor requirements,
material events, foreign snapshot/authority rejection, and refusal of a second
strategy book. Remove new guards to prove the tests detect their absence.
Existing legacy paper and action tests must continue to pass. This work grants
no NAS deployment, real broker contact, certificate issuance or paper activation.

The paper decomposition audit retains its frozen historical manifest. Record
the intentionally changed paper functions in the existing post-decomposition
delta manifest, with their new AST hashes and original historical hashes.
These records describe source changes; no economic golden output is repinned.
