The owner authorized a local root-cause patch after the November 10 opening
cycle retired its immutable plan because two recorded native fees changed its
cash baseline. The plan remains `SUPERSEDED`; installation cannot execute it,
relabel it successful, create a successor plan or change command history.

`SUPERSEDED / POST_PLAN_CASH_ACTIVITY_RECONCILED`, with a completed current-day
cycle, its original immutable plan and sizing authority, a positive complete

Fresh GET-only native positions must equal the positive reconciliation and
there must be no open broker orders. Financial state, PostgreSQL storage,
notifications, command/fill history, backup policy and immutable plan bytes
remain subject to the existing preservation checks at every real boundary.

The final dashboard must report a current, positively proved clean skip and
waiting for the next ordinary decision, retaining the skipped run and original
reason. It must not claim a filled or successful run or invent a next plan.
Strict source/currentness and finite publication/readiness deadlines still
apply. Historical review remains visible until separately acknowledged through
the ordinary supported contract; installation never acknowledges it.

This expands software-installation admission only. It does not expand financial

positive check completes. The installer's pending classifier must recognize

PAPER_VERIFICATION/CHECKING fact, automatic FINANCIAL_VERIFICATION phase and its

pending-only classification under the unchanged original installation cutoff;
