# Opening status and reference validation

The market-data storage query changes preserve the order and content of every row used by the economic compiler. The source identity recognizes the complete verified old or new storage implementation together with the same compiler and SQL routing contract. An unreviewed file, partial replacement or changed reference layout must invalidate that identity. The action-history traversal continues to admit only individually reviewed layout implementations.

During a guarded opening, the writer may reuse the result of replaying control events while it holds both the publication and writer locks. Each use checks the physical relation and row versions of the complete event history and compares the result with the current control singleton. Lease, clock, account, broker operation and kill checks remain current for each request. The alert supervisor's health reader validates the runtime schema on its first probe and after a change to the database identity, DDL audit, or delivery tables. It checks current delivery state, the database clock and dead letters on every probe. A missing audit or standalone diagnostic requires full schema validation.

The panel may classify a missed buy as recoverable only when the current plan and account observations establish exactly which orders remained unsent. An older PLANNED command can coexist with that proof only if its earlier cycle, account, supersession and command history establish that it never reached transport. Every other unresolved command continues to block this classification. The panel keeps current missed orders distinct from historical commands when displaying and saving evidence.

An account view may report several working orders from the same funded market-buy plan. Each order needs its own matching command identity, side, symbol, amount and broker observation. Foreign, duplicate or ambiguous orders invalidate the group. Reporting status does not authorize transport.

Normalized market-data validation reads only the reference rows belonging to the selected candidate and the individual block headers they identify. Each expected reference and its metadata must still match the complete sealed layout. This changes how PostgreSQL accesses the data while retaining checks for missing and mismatched headers. Health probes should verify the evidence required by the process they monitor, while financial authority continues to be checked at the point of use.
