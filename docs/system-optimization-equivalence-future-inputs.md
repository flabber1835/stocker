# Bounded equivalence with a later identical factual successor

The original bounded equivalence helper admitted only a completed reference
whose input-repair list never changed after its selected 2017 checkpoint.
TGI's actual 2025 continuation introduces a later repair, so that restriction
cannot be silently removed. This document defines the stronger proof required
to reuse the completed reference for the common-facts numerical analysis.

Write the deterministic financial transition as
`(S[t+1], B[t+1], A[t+1]) = F(S[t], B[t], A[t], x[t])`, where S is the entire
canonical state, B the entire adapter buffer and A all account/reporting/retry
state. Source and fixed input identities must be identical. No broker state
or randomness enters this recurrence.

Replay from P00's own July31,2017 checkpoint with the additional, corrected
Winter, Spring, grouped follow-up and TGI ordinary input components, through
April30,2019. Compare every committed formation/daily/monthly record, complete
canonical state, financial/reporting/retry state and bit-exact buffer material
against the original own cutoff checkpoint. Any mismatch refuses equivalence.
The buffer comparison includes every ring field and typed floating-point bit
pattern, not just holdings, NAV or a feature sample.

After that cutoff the old and new suppress/add action maps must be identical,
including every payload field and the native-term SHA used for suppression.
Additional old input successors must all be ordinary terminal-repair documents,
bound to their actual own future predecessor and committed watch event. Their
resume dates and every affected date must be later than the cutoff. Canonically
restore the actual predecessor and verify the event's state/input identities.
An extra old action, changed cash amount, changed successor, or changed date
refuses the proof. Earlier retained repair descriptors must match exactly.

The frozen backtest changes an input binding with
`replace(run, input_sha256=...)`, retaining the same canonical state. The
frozen runtime advances from `run.state` and the published observation; account
and retry transitions also receive state/observations, not the run input hash.
Thus these verified later rebindings change lineage hashes without changing
the financial recurrence. This source argument applies only to the pinned
unchanged financial kernel and identical policy. Source changes or an
unaccounted successor refuse the certificate.

Equality of complete recurrence state at the cutoff and of every later input
then implies equality of the later financial path by induction. The proof
does not rewrite or relabel any old checkpoint, journal, capture or physical
book. It produces a separately authenticated semantic-equivalence certificate
linking the actual new prefix to the actual old completed path. Numerical
admission must explicitly authenticate that certificate and its independent
review; an unreviewed JSON assertion is insufficient.

Old cutoff/predecessor snapshots may now live in nested immutable lineage.
Choose only an exact source/base/repair-bound snapshot with the required date;
multiple distinct eligible checkpoint identities refuse selection. Verify its
actual bytes and canonical restore, not its pathname alone.

A failed certificate is retained as a negative result. Independently review
and preserve any actual stopped corrected prefix so it can continue from its
own current checkpoint; never restart the origin or adopt unknown output.
No certificate or economic result exists until actual hosted evidence passes.
PAPER, deployment and production source remain untouched.

The proof export preserves the exact incoming encrypted ancestor ZIP as an
opaque SHA-bound member, alongside the new physical prefix and reviews. This
retains every original checkpoint/journal/tail byte without duplicating the
expanded old tree in the next export. The old ZIP and extracted old tree stay
unchanged on the hosted VM. Subsequent numerical admission authenticates the
original financial export and this proof separately.

explicitly select512MiB for an exact SHA/length-pinned large completed source;
no other cap is permitted. The1GiB plaintext inventory limit and all existing
