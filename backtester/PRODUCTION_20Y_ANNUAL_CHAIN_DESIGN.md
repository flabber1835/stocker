# Production-only 20-year annual replay contract

Date: 2026-08-31

Scope: `research/backtester` only. Production `main` remains read-only and pinned
to `887f479b15ad861313da666ad698034d3847121c`.

## Decision

The strict-PIT production replay runs as one authenticated chronological chain
with one GitHub Actions job per calendar year, 2006 through 2026. The jobs are
declared in one workflow and joined by explicit `needs` dependencies. A
successful year writes the complete restart image generated by that chronology;
the next job downloads that exact artifact. It does not run the research
comparator and it never uses prerecorded decisions, positions, or future state.

This replaces the single 360-minute production job. The observed 2006
production segment completed in about 22 minutes. Each replay step is limited
to 300 minutes and each job to 350 minutes, leaving 50 minutes for checkout,
canonical-package verification, certificate creation, and artifact transport.
The 1.5 GB canonical package is pulled and hash-verified in each job but is not
uploaded again. Only the compressed checkpoint, certificate, result summary,
failure context, and log cross the job boundary.

## Checkpoint format 3

Schema `backtester.production-year-checkpoint/3` is a strict, content-addressed
envelope. Its canonical payload and complete file both have SHA-256 witnesses.
A resume rejects missing, extra, mistyped, non-finite, out-of-range, or
identity-inconsistent data.

The authenticated payload owns:

1. The exact experiment, backtester source, pinned production source, applied
   production overlay, checkpoint implementation, canonical manifest, and
   canonical dataset identities.
2. The chain start, measurement start, full dataset end, segment year, final
   session, canonical session hash, processed-session pointer, exact next
   session/hash witness, and predecessor checkpoint digest.
3. Both required production-harness `SessionState` restart images and their
   independently recomputed state hashes.
4. Both required overlay accounts, including NAV, effective and pending
   exposure, initialization, transition cost, and transition count. Only the
   semantic Production account is exposed in logs, certificates, and results.
5. Split factors, observation counts, prior signal closes, latest causal ticker
   bindings, and the prior Wealth Core close.
6. Full-stack production module state: the production Wealth Core prior close,
   cumulative per-session production Wealth Core open/close evidence, metadata
   counters, strict issuer-authority counters, and progress-session count.
7. The complete daily prefix as an explicit ordered 19-column schema plus row
   arrays and a prefix digest. Row objects are not serialized because JSON
   key-sorting changed resumed CSV column order in checkpoint format 2.

On restore, dates must equal the exact canonical session prefix; the pointer,
last session, session hashes, and next-session witness must agree; account NAVs
must equal the last daily row; Wealth Core prior closes must equal their final
daily/core-history observations; module counters and map domains must be exact;
and restored production states must reproduce the recorded state hashes.

The predecessor digest is forbidden for the 2006 genesis checkpoint and is
mandatory for every later year. A new chain starts at 2006; format-2 checkpoints
are not accepted.

## Equivalence gate

Before the 2006 checkpoint is certified, the workflow runs a bounded production
equivalence test in fresh processes:

- uninterrupted production through the 2007 year end; and
- production through the 2006 year end, checkpoint, restore, and continuation
  through the same 2007 year end.

The gate requires identical final production state hashes, account state,
module-owned continuation state, ordered daily evidence, metrics, summary, and
finalized output hashes. This specifically covers the independent strict-PIT
Wealth Core prior-close stream that format 1 omitted and the output-column order
that format 2 failed to preserve.

## Failure policy

The exact-next-open accounting guard remains fail-closed. If production has a
pending exposure change while a held security has no resolved open, the run
records the session, unresolved permanent security IDs, held episodes/source
lots, effective and pending exposures, and pending terminal state, then exits.
No checkpoint certificate or next-year dispatch is issued. The prior PASS
checkpoint remains the retry boundary.

Artifacts are uploaded with `if: always()`. Certificate creation is
success-only, and the explicit job dependency prevents the next year from
starting after failure. Missing or corrupt sidecars, checkpoint hashes,
predecessor links, canonical identities, or exact source identities stop the
chain before any resumed economic session executes.

The prior failure was reproduced exactly at 2008-03-24 for PHRM security
`705177744622024105`. The canonical package carried an incomplete cash-merger
row even though the effective 2008-03-07 terms were $25 cash plus 0.8367 CELG
shares. The replay now replaces only that incomplete canonical row with the
checksum-authenticated exact terms (including fractional-share settlement).
The fail-closed accounting guard itself is unchanged. An exact resumed replay
passed the former boundary and checkpointed through 2008-03-31.

## User-facing reporting

Logs, certificates, metrics, summaries, daily output, and the GitHub job summary
use **Production** exclusively for the strategy account. No experimental account
designation is part of the public result. The `1.000000` value in the failed
run was an inert harness scaffold, not an allocation or a production result.

Every completed quarter and annual certificate reports:

- Production ending multiple from the 2006-07-31 measurement anchor;
- cumulative Production CAGR through the completed session; and
- the matching SPY figures where a completed result bundle is available.

Only the final 2026 segment may publish the required 5/10/15/20/max headline
metrics as a complete 20-year result.
